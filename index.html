Computational Features for Symbolic Melody Analysis

符號旋律分析的計算特徵

David M. Whyatt, Peter M. C. Harrison
arXiv:2608.19061 · cs.SD · 投稿submitted 2026-08-19
abspdfhtmlcited by
為什麼挑這篇：這篇論文的分類器在區分中國與歐洲民謠(Essen Folksong Collection)上,用完整 235 個特徵做五折交叉驗證達到 98.74±0.29% 準確率,測試集只錯分 873 首裡的 7 首(99.20%);壓縮成 8 個因子後準確率降到 92.56%,用不到 7 個百分點的準確率換來大幅提升的可解釋性。同一套資料上,作者重現的九套既有工具箱裡,jSymbolic(125 特徵)拿到 98.25%,FANTASTIC(40 特徵)96.96%,SIMILE(3 特徵)只有 76.49%,顯示特徵數量與品質直接影響分類力。Why this one: On the Essen Folksong Collection's Chinese-vs-European classification task, the full 235-feature set reaches 98.74±0.29% under 5-fold cross-validation and 99.20% on the held-out test set (7 of 873 melodies misclassified); collapsing to an 8-factor solution costs under 7 points of accuracy (92.56%) in exchange for interpretability. Re-running nine prior toolboxes on the same data, jSymbolic (125 features) scores 98.25%, FANTASTIC (40 features) 96.96%, and SIMILE (3 features) only 76.49%.

動機Motivation

音樂學與音樂心理學裡描述旋律的計算特徵,長年分散在不同年代的書籍、論文與技術報告裡,彼此用不同程式語言實作,版本片段化,難以在同一套資料上互相比較。這篇論文要解決的不是「發明新特徵」,而是把散落各處的旋律特徵定義收斂成一套可重現、可互相比較的工具,讓音樂學、音樂心理學與 MIR 研究者能用同一套程式碼起步,而不必每次都重寫一遍別人已經做過的事。

Computational features for describing melody have accumulated across decades of books, articles, and technical reports, implemented in different languages with fragmented, hard-to-compare versions. This paper's goal isn't inventing new features but converging scattered definitions into one reproducible, comparable toolkit, so musicology, music psychology, and MIR researchers can start from the same code instead of re-implementing what others already built.

背景與相關研究Introduction & Prior Work

現有工具箱各有偏好也各有缺口。FANTASTIC(R)用旋律 n-gram(m-type)但不保留時間結構;jSymbolic(Java)號稱 1,500 個特徵,但多數是直方圖分箱灌出來的數量,認知理論基礎比對手弱;IDyOM(Common Lisp)用變階馬可夫模型算旋律驚訝度,實作了 Narmour 的期望-實現理論;MIDI Toolbox(MATLAB)偏向視覺化,摘要統計量有限;MUST(MATLAB)只留下不對稱性、平衡性等少數特徵;SIMILE/melsim(C++/R)做旋律相似度但 SIMILE 已無人維護;Partitura(Python)專注演奏對齊,旋律分析功能薄弱。

這篇論文的作法是把上述工具箱的特徵全部收進一個 Python 套件,依認知理論篩選、去除冗餘(例如剔除 FANTASTIC 裡 18 個缺乏理論依據的變體,以及 jSymbolic 僅適用複音音樂的特徵),而不是再發明一種分類法。

Existing toolboxes each have their own gaps. FANTASTIC (R) uses melodic n-grams (m-types) but discards temporal structure; jSymbolic (Java) claims 1,500 features, many inflated by histogram bins, with weaker cognitive grounding than rivals; IDyOM (Common Lisp) models melodic surprise with variable-order Markov chains implementing Narmour's Implication-Realisation theory; MIDI Toolbox (MATLAB) is visualization-oriented with limited summary statistics; MUST (MATLAB) keeps only a handful of features like asymmetry and balance; SIMILE/melsim (C++/R) targets melodic similarity but SIMILE itself is unmaintained; Partitura (Python) is performance-alignment-focused with thin melody analysis.

This paper's move is to fold all of these into one Python package, curated by cognitive-theory relevance and pruned for redundancy (e.g., dropping 18 FANTASTIC variants with no clear theoretical basis and jSymbolic's polyphony-only features) -- not to invent yet another taxonomy.

方法Method

套件把 282 個特徵歸成三大類、十二個概念類別:音高(絕對音高、音程、Parsons/Huron 輪廓、音級分布、Krumhansl-Schmuckler 調性)、節奏(起始時間、IOI 比率、Longuet-Higgins & Lee 切分音模型)、以及音高與節奏合併的特徵(m-type 詞彙多樣性、Shannon 熵、Narmour 期望原則、語料庫詞頻)。多數特徵是新實作,melsim 透過 R 介面包裝進來,部分程式碼改自 Apache 2.0 授權的 Partitura。

作者在 Essen Folksong Collection(8,472 首民謠,清掉 93 首損壞或重疊音符後剩 8,379 首,平衡取樣成 2,173 首中國、2,192 首歐洲共 4,365 首)上做邏輯回歸分類:完整 235 個數值特徵五折交叉驗證達 98.74±0.29%,測試集(873 首)只錯 7 首(99.20%)。用探索性因子分析(斜交 promax 轉軸)把特徵壓成 8 個因子(解釋 46.27% 變異,包含長節奏、不規則節奏、音級多樣性等),分類準確率降到交叉驗證 94.33±0.38%、測試集 92.56%,用不到 7 個百分點的準確率換取可解釋性。

The package groups 282 features into three top-level domains and twelve conceptual categories: pitch (absolute pitch, interval, Parsons/Huron contour, pitch-class distribution, Krumhansl-Schmuckler tonality), rhythm (onset timing, IOI ratios, Longuet-Higgins & Lee syncopation), and combined pitch-rhythm features (m-type lexical diversity, Shannon entropy, Narmour expectation, corpus document frequency). Most features are newly implemented; melsim is wrapped via an R interface, and some code is adapted from the Apache-2.0-licensed Partitura.

On the Essen Folksong Collection (8,472 folk songs, reduced to 8,379 after removing 93 corrupted/overlapping ones, balanced to 4,365 -- 2,173 Chinese, 2,192 European), logistic regression on the full 235 numeric features reaches 98.74±0.29% under 5-fold cross-validation and 99.20% on the 873-song test set (7 misclassified). Compressing to 8 factors via exploratory factor analysis (oblique promax rotation, 46.27% variance explained) drops accuracy to 94.33±0.38% cross-validated / 92.56% test, trading under 7 points of accuracy for interpretability.

限制Limitations

作者自己列出四點限制。一是複音旋律處理不了,套件偵測到複音輸入就拒絕計算,得先用音源分離抽出單旋律線;二是調性演算法只涵蓋大小調,套用到非西方音樂或當代音樂時代表性有限;三是整套特徵取向「必然是西方中心」,因為現有文獻本身就以西方樂理為主;四是目前完全沒有能直接吃音訊、做旋律分析的特徵工具箱,這個套件也不例外,只能處理符號化(如 MIDI/MusicXML)輸入。

The authors name four limitations themselves. First, the package cannot handle polyphonic melodies -- it refuses to compute on detected polyphonic input, requiring source separation to extract a monophonic line first. Second, the tonality algorithm only covers major/minor modes, limiting applicability to non-Western or contemporary music. Third, the whole feature set is "necessarily Western-centric," since the underlying literature itself is. Fourth, no feature-based toolbox -- this one included -- currently operates directly on audio; everything requires symbolic (e.g. MIDI/MusicXML) input.

討論Discussion

這篇論文最有說服力的部分是同一套資料上重跑九套既有工具箱做對照:melody-features(235 特徵)98.74%,jSymbolic(125 特徵)98.25%,FANTASTIC(40 特徵)96.96%,MUST(20 特徵)95.62%,MIDI Toolbox(22 特徵)93.07%,IDyOM(18 特徵)85.77%,SIMILE(3 特徵)只有 76.49%。這個梯度顯示特徵數量與理論覆蓋度確實直接影響分類力,而不只是把各家工具箱簡單相加。

作者將此定位為基礎設施:讓音樂學、音樂心理學、MIR 三個社群共用同一套可重現、有超連結原始碼的特徵目錄,而不是每個實驗室各自維護一份不完整的實作。

The strongest evidence here is the head-to-head re-run of nine prior toolboxes on the same data: melody-features (235 features) 98.74%, jSymbolic (125) 98.25%, FANTASTIC (40) 96.96%, MUST (20) 95.62%, MIDI Toolbox (22) 93.07%, IDyOM (18) 85.77%, and SIMILE (3) only 76.49%. This gradient shows feature count and theoretical coverage genuinely drive classification power, not just that combining toolboxes helps.

The authors frame the contribution as infrastructure: one reproducible, hyperlinked feature catalogue shared across musicology, music psychology, and MIR, instead of each lab maintaining its own incomplete implementation.

Finetuning Strategies for Querying Sounds by Vocal Imitation

以人聲模仿查詢音效的微調策略

Aditya Bhattacharjee, Christos Plachouras, Sungkyun Chang, Emmanouil Benetos
arXiv:2608.19174 · cs.SD, cs.AI, cs.IR · 投稿submitted 2026-08-20
abspdfhtmlcited by
為什麼挑這篇：在 AES AIMLA 2025 挑戰賽的驗證集上,方案二(共享 MobileNetV3 + 混合對比/三元組損失)拿到 MRR 0.2932、NDCG 0.6468,方案一(凍結 CED 編碼器 + 監督式對比學習)拿到 MRR 0.2876、NDCG 0.6600,兩者都超過先前方法 Greif et al.(2024)的 MRR 0.2726、NDCG 0.6463,更遠勝隨機基線的 MRR 0.0444。但兩份方案在 MRR 與 NDCG 上排名互換,顯示「檢索到最相關那一個」跟「整體排序品質」不是同一件事。Why this one: On the AES AIMLA 2025 Challenge validation set, Submission #2 (shared MobileNetV3 with a hybrid contrastive/triplet loss) reaches MRR 0.2932 / NDCG 0.6468, while Submission #1 (frozen CED encoder with supervised contrastive learning) reaches MRR 0.2876 / NDCG 0.6600 -- both ahead of the prior Greif et al. (2024) method's MRR 0.2726 / NDCG 0.6463, and far ahead of the random baseline's MRR 0.0444. Yet the two submissions swap rank on MRR versus NDCG, showing that retrieving the single best match and getting the overall ranking right aren't the same thing.

動機Motivation

Query by Vocal Imitation(QbVI)讓使用者用哼唱或模擬聲音去檢索音效資料庫,不必打關鍵字,對非語言、難以命名的聲音(如某種機械聲、特定鳥鳴)特別有用。這篇論文的動機是人類發聲的變異度和音效類別的聲學多樣性都很大,系統得同時學會忽略「同一個人怎麼哼都算同一類」與「不同人哼同一個聲音也算同一類」這兩種變異,才能把用嘴巴模仿的聲音跟資料庫裡真正的錄音配對起來。

Query by Vocal Imitation (QbVI) lets a user retrieve sounds from an audio database by humming or vocally mimicking them, useful for non-verbal or hard-to-name sounds -- a specific mechanical noise, a particular bird call -- that are awkward to type as keywords. The motivation is that both human vocalization and the acoustic diversity of sound classes vary widely, so a system must bridge two kinds of variation at once -- one person's repeated imitations of the same sound, and different people's imitations of the same sound -- to match a vocal mimicry against real recordings.

背景與相關研究Introduction & Prior Work

這個題目上,早期做法用自編碼器的隱藏層特徵接距離比對,後來出現用對比損失訓練的半共享(semi-Siamese)卷積架構。Greif et al.(2024)進一步證明雙塔(dual-tower)MobileNetV3、以 SimCLR 風格對比目標微調的效果。

這篇論文並非提出全新架構,而是拿 AES AIMLA 2025 挑戰賽的兩份參賽方案做對照:方案一凍結一個以 ViT 為底的 CED 音訊編碼器只微調投影頭;方案二則用單一共享(而非雙塔)的 MobileNetV3,搭配監督式對比損失加三元組損失的混合目標。訓練資料上,VimSketch 提供已知配對的(參考音、模仿音)監督樣本,VocalSketch 裡沒被收進 VimSketch、有類別標籤的模仿音則被當成結構化負樣本。

Prior work here ranged from autoencoder bottleneck features compared by distance, to semi-Siamese convolutional architectures trained with contrastive loss. Greif et al. (2024) pushed this further with a dual-tower MobileNetV3 fine-tuned with SimCLR-style contrastive objectives.

This paper proposes no new architecture; instead it contrasts two AES AIMLA 2025 Challenge submissions: Submission #1 freezes a ViT-based CED audio encoder and fine-tunes only a projection head, while Submission #2 uses a single shared (not dual-tower) MobileNetV3 with a hybrid supervised-contrastive-plus-triplet objective. For training data, VimSketch supplies supervised (reference, imitation) pairs with known correspondence, while VocalSketch imitations excluded from VimSketch but carrying class labels serve as structured negatives.

方法Method

方案一把凍結的 CED-base 編碼器(輸出 768 維)接一個輕量 MLP 投影頭,映射到 256 維空間,用 VimSketch 配對做監督式對比學習,溫度 τ=0.07,批量 128,訓練 50 epoch。

方案二用單一共享的 MobileNetV3 編碼器,從倒數第二層輸出 960 維嵌入,輸入是 32kHz、10 秒音訊算出的 128 頻帶 log-Mel 頻譜;損失是監督式對比損失加上以半困難負樣本(semi-hard negative,依 AudioSet 本體類別從排除的 VocalSketch 子集取樣)做三元組損失(邊界 0.6),並依當前活躍三元組數量動態調整三元組損失權重;批量 64、訓練 30 epoch。兩個方案都對查詢與參考音訊同步做時間平移、增益調整、變調、變速、加高斯雜訊等增強。

Submission #1 attaches a lightweight MLP projection head to a frozen 768-dim CED-base encoder, mapping to a 256-dim space and training on VimSketch pairs with supervised contrastive loss (temperature 0.07, batch size 128, 50 epochs).

Submission #2 uses a single shared MobileNetV3 encoder outputting 960-dim embeddings from the penultimate layer, fed 128-band log-Mel spectrograms from 32kHz, 10-second audio; its loss combines supervised contrastive loss with a semi-hard-negative triplet loss (margin 0.6, negatives drawn from the VocalSketch subset excluded from VimSketch via AudioSet ontology labels), with the triplet term dynamically reweighted by the count of active triplets, trained at batch size 64 for 30 epochs. Both submissions apply matched augmentation (time shift, gain, pitch shift, time stretch, Gaussian noise) to query and reference audio alike.

限制Limitations

論文本身沒有專門的限制章節。從結果推敲,兩份方案在指標上互有取捨:方案二的 MRR(0.2932)略勝方案一(0.2876),但方案一的 NDCG(0.6600)反而略高於方案二(0.6468),代表「排名第一名的準確度」跟「整體相關性排序品質」不完全一致,論文沒有進一步解釋這個落差。另外,對照組 2DFT 的 MRR 只有 0.1262,顯示這個任務本身難度不低,而兩份方案相對隨機基線(MRR 0.0444)的提升雖然明顯,絕對數值(MRR 均低於 0.3)仍偏低,離「好用的檢索系統」還有明顯差距。

The paper has no dedicated limitations section. Reading the results, the two submissions trade off against each other: Submission #2's MRR (0.2932) edges out Submission #1 (0.2876), yet Submission #1's NDCG (0.6600) is higher than Submission #2's (0.6468) -- meaning top-rank accuracy and overall ranking quality don't fully agree, a gap the paper doesn't explain further. The 2DFT baseline's MRR of only 0.1262 also signals the task itself is hard, and while both submissions clearly improve over the random baseline (MRR 0.0444), their absolute MRR values (both under 0.3) remain low -- still some distance from a retrieval system that feels reliably usable.

討論Discussion

這篇論文的價值不在提出新模型,而在同一個挑戰賽基準上把兩條路線的效果量化到可比較的地步:方案一(遷移學習、凍結預訓練編碼器)MRR 0.2876、NDCG 0.6600;方案二(結構化負樣本、混合損失)MRR 0.2932、NDCG 0.6468,雙雙勝過 Greif et al.(2024)的 MRR 0.2726、NDCG 0.6463,也遠勝隨機基線的 MRR 0.0444。作者的結論是「謹慎的預訓練」與「結構化負樣本設計」是兩條互補、都能有效提升 QbVI 檢索表現的路,方案二已經部署在 thatsoundslike.me 這個實際網站上。

This paper's value isn't a new model but quantifying two competing recipes on the same challenge benchmark to where they're directly comparable: Submission #1 (transfer learning, frozen pretrained encoder) reaches MRR 0.2876 / NDCG 0.6600; Submission #2 (structured negative sampling, hybrid loss) reaches MRR 0.2932 / NDCG 0.6468 -- both beating Greif et al. (2024)'s MRR 0.2726 / NDCG 0.6463 and far outperforming the random baseline's MRR 0.0444. The authors conclude that careful pretraining and structured negative-sample design are two complementary, independently effective paths to better QbVI retrieval; Submission #2 is already deployed at the live site thatsoundslike.me.

FM Synthesizer Audio-Parameter Shared Embeddings

FM 合成器的音訊-參數共享嵌入

David Braun, Adam Finkelstein
arXiv:2608.18226 · cs.SD · 投稿submitted 2026-08-18
abspdfhtmlcited by
為什麼挑這篇：這篇論文最反直覺的地方是:模型容量跟泛化能力並不成正比。DX7-GNN 只用 338 萬參數,在保留一半合成器拓樸不給訓練看的測試上做到 R@1 52.2%,比參數量多 17 倍的 Transformer(5,720 萬參數,R@1 34.6%)高出將近 18 個百分點,比 Highway Network(R@1 24.8%)高 27 個百分點。而且這個泛化能力幾乎全靠訓練時的算子交換增強撐起來——拿掉它,DX7-GNN 自己的 R@1 就從 52.2% 崩到 13.5%,證明真正在教模型「拓樸可以互換」的是資料增強,不是架構本身單獨的功勞。Why this one: The most counterintuitive result here is that model capacity and generalization pull apart. DX7-GNN, with only 3.38M parameters, reaches R@1 52.2% on a test that withholds half the synthesizer topologies from training -- nearly 18 points ahead of the 57.2M-parameter Transformer (R@1 34.6%, 17x more parameters) and 27 points ahead of the Highway Network (R@1 24.8%). And that generalization leans almost entirely on the operator-swap augmentation used during training: remove it, and DX7-GNN's own R@1 collapses from 52.2% to 13.5%, showing the augmentation -- not the architecture alone -- is what actually teaches the model that topologies are interchangeable.

動機Motivation

音效設計師想找到心裡想的合成器音色,常常只能在龐大的預設庫裡一個一個試聽,非常沒效率。這篇論文指出現有做法把合成參數當成扁平向量處理,等於丟掉了訊號路由方式跟參數之間交互作用產生的聲音結構——把 Yamaha DX7 這種六個算子可以接成 32 種拓樸的合成器,硬是用一個類別標籤代表演算法,模型自然學不到「換一種拓樸結構」時聲音會怎麼變,也就沒辦法泛化到訓練時沒見過的路由方式。

Sound designers routinely audition preset libraries one by one, hunting by ear for a timbre they have in mind -- a slow, inefficient search. This paper argues existing methods treat synthesis parameters as flat vectors, throwing away the signal-routing structure and parameter interactions that actually shape the sound. Take the Yamaha DX7, whose six operators can be wired into 32 distinct routing topologies: encoding "which algorithm" as a single categorical label means a model never learns how sound changes under a different routing structure, so it cannot generalize to topologies unseen during training.

背景與相關研究Introduction & Prior Work

自動合成器編程這個題目上,先前做法包括監督式回歸(Yee-King et al., 2018)、梯度優化、演化搜尋(NAS-FM, Ye et al., 2023)、以及強化學習(InverSynth II, Barkan et al., 2023)。專門處理 FM 合成的工作裡,NAS-FM 同時搜尋拓樸與頻率比,但沒辦法幫沒見過的拓樸編碼預設;DiffMoog 這個可微分模組化合成器發現 FM 調變鏈在梯度優化下很難收斂;Le Vaillant et al.(2024)學到了 DX7 的編碼,但演算法仍是 one-hot 類別參數,一樣無法泛化到新拓樸;Param2Tok(Hayes et al., 2025)編碼參數並找出置換對稱性,但訊號路由依然是 one-hot。

另一條線是把 CLAP(Elizalde et al., 2023)的音訊-文字對比學習目標,換成 SLAP(Guinot et al., 2025)這種非對比、BYOL 風格的訓練方式,在檢索上勝過 CLAP。這篇論文的差異在於同時做兩件事:把 SLAP 的訓練目標從音訊-文字改成音訊-參數配對,並設計一個訊息傳遞方式模仿 FM 訊號處理本身的圖神經網路參數編碼器,靠共享權重讓網路可以處理訓練時沒見過的任意拓樸。

Prior work on automatic synthesizer programming spans supervised regression (Yee-King et al., 2018), gradient-based optimization, evolutionary search (NAS-FM, Ye et al., 2023), and reinforcement learning (InverSynth II, Barkan et al., 2023). Within FM synthesis specifically, NAS-FM searches jointly over topology and frequency ratios but cannot encode presets for unseen topologies; DiffMoog, a differentiable modular synthesizer, reports FM modulation chains failing to converge under gradient optimization; Le Vaillant et al. (2024) learn DX7 encodings but still treat the algorithm as a one-hot categorical parameter, again blocking generalization to new topologies; Param2Tok (Hayes et al., 2025) encodes parameters and discovers permutation symmetries but keeps routing as one-hot.

Separately, CLAP (Elizalde et al., 2023) built joint audio-text embeddings via contrastive learning, and SLAP (Guinot et al., 2025) replaced the contrastive objective with a non-contrastive, BYOL-style one that outperforms CLAP on retrieval. This paper's departure is doing both at once: adapting SLAP's objective from audio-text to audio-parameter pairs, and designing a graph neural network parameter encoder whose message passing imitates FM signal processing itself, with shared weights letting it handle arbitrary topologies never seen in training.

方法Method

核心是 DX7-GNN:把六個算子當成圖節點,調變連接與回授迴路當成有向邊,145 個 DX7 參數(123 個 [0,1] 浮點數、22 個整數)先轉成每個節點 47 維特徵,再用輸入 MLP 投影到 384 維基底特徵。九層(L=9)訊息傳遞裡,每層先依邊權重(調變邊權重 1,回授邊權重是可學習的單調重映射乘上一個可學習係數)聚合鄰居訊息,再用 FiLM(特徵層級線性調製)把聚合訊息注入基底特徵,做完層正規化與殘差連接後,乘上重映射過的輸出電平——這一步刻意模仿 DX7 真正的訊號流程。所有節點在所有層共享同一套訊息傳遞權重,這是讓模型能吃任意拓樸、又不會因為深度增加而過度平滑的關鍵設計。訓練目標把 SLAP 的線上/目標雙編碼器架構(EMA 更新率 τ=0.98)從音訊-文字換成音訊-參數,在 3.14 萬筆 DX7 預設(DX7AllTheWeb 資料集)上訓練。

在所有 32 種演算法都訓練過的隨機切分下,DX7-GNN 與 Transformer 打成平手(R@1 86.1%、R@10 99.5%、MRR 0.917);但換成刻意保留一半拓樸不給訓練看的「交錯演算法切分」測試泛化能力時,DX7-GNN 的 R@1 52.2%、R@10 88.5%、MRR 0.652,大幅超過 Transformer(R@1 34.6%、MRR 0.470)與 Highway Network(R@1 24.8%、MRR 0.365),而且 DX7-GNN 只用 338 萬參數,比 Transformer 的 5,720 萬參數少了 94%。消融實驗顯示,拿掉算子交換增強後 R@1 從 52.2% 崩到 13.5%,拿掉回授邊則降到 49.5%,改用全連接拓樸更是掉到 30.9%,證明真正的路由結構、而不只是模型容量,才是泛化的關鍵。

The core is DX7-GNN: operators become graph nodes, modulation connections and feedback loops become directed edges. The 145 DX7 parameters (123 continuous floats in [0,1], 22 integers) are first turned into 47-dim per-node features, then projected by an input MLP to 384-dim base features. Across 9 message-passing layers, each layer aggregates neighbor messages weighted by edge type (modulation edges weight 1; feedback edges weighted by a learned monotonic remapping times a learned scalar), injects the aggregated message into the base features via FiLM conditioning, then multiplies the result -- after layer norm and a residual connection -- by a remapped output level, deliberately mirroring DX7's actual signal flow. All nodes share the same message-passing weights across all layers, the key design letting the model handle arbitrary topologies without oversmoothing as depth grows. The SLAP training objective's online/target dual-encoder setup (EMA rate τ=0.98) is adapted from audio-text pairs to audio-parameter pairs, trained on 31,443 DX7 presets from the DX7AllTheWeb dataset.

Under a random split where all 32 algorithms appear during training, DX7-GNN ties with the Transformer baseline (R@1 86.1%, R@10 99.5%, MRR 0.917); but under an interleaved-algorithm split that deliberately holds out half the topologies to test generalization, DX7-GNN reaches R@1 52.2%, R@10 88.5%, MRR 0.652 -- far ahead of the Transformer (R@1 34.6%, MRR 0.470) and Highway Network (R@1 24.8%, MRR 0.365) baselines, despite using only 3.38M parameters versus the Transformer's 57.2M (94% fewer). Ablations confirm the routing structure itself matters: removing the operator-swap augmentation collapses R@1 from 52.2% to 13.5%, removing feedback edges drops it to 49.5%, and switching to a fully-connected topology drops it further to 30.9% -- capacity alone doesn't explain the gap.

限制Limitations

作者列出五點限制:一、評測只做在 DX7 這種算子結構完全相同的合成器上,能否泛化到結構迥異的其他合成器還不清楚;二、3.14 萬筆預設在 32 種演算法間分布不均(每種 116 到 3,758 筆不等);三、每筆預設只在單一音高與力度(C4、velocity 85)上render,沒有涵蓋音高、力度相關的音色變化;四、所有結果都只跑了一次訓練,超參數搜尋是在凍結的音訊編碼器潛在特徵上做,而不是更昂貴的端到端搜尋;五、音訊編碼器完全沒碰過複音 MIDI,作者認為這會是更有用的後續方向。

The authors list five limitations: (1) evaluation covers only the DX7, whose operators are structurally identical, so generalization to synthesizers with heterogeneous structure is untested; (2) the 31,443 presets are imbalanced across the 32 algorithms (116 to 3,758 presets each); (3) every preset is rendered at a single pitch and velocity (C4, velocity 85), missing pitch- and velocity-dependent timbre variation; (4) all results come from single training runs, and the hyperparameter search used frozen audio-encoder features rather than costlier end-to-end search; (5) the audio encoder was never trained on polyphonic MIDI, which the authors flag as a more useful future direction.

討論Discussion

這篇論文最能撐住「結構歸納偏好有用」這個主張的,是消融實驗裡數字一路往下掉的軌跡:52.2%(完整模型)、49.5%(拿掉回授邊)、30.9%(全連接拓樸)、13.5%(拿掉算子交換增強),四個數字排成一列,講的是同一件事——路由結構本身帶進來的資訊,不是靠模型容量硬補就能補上的。

另一個佐證是 timbremetrics 三元組一致性測試:這個只在 FM 合成資料上訓練的音訊編碼器拿到 68.4~69.3%,已經逼近在海量通用音訊資料上訓練的 LAION-CLAP(70.8~71.8%)。作者也誠實地把「輸出電平重映射學出跟 DX7 指數增益曲線相似的凸函數」這種可解釋的副產品秀出來,但沒有誇大——強調這只是在單一合成器、單一取樣點上驗證,還沒證明能推廣到異質合成器或效果鏈這種更複雜的圖結構。

The strongest support for "structural inductive bias matters" here is the descending trail of ablation numbers: 52.2% (full model), 49.5% (no feedback edges), 30.9% (fully-connected topology), 13.5% (no operator-swap augmentation) -- four numbers in a row all pointing at the same fact, that the information carried by routing structure itself can't be substituted for with raw model capacity.

A second piece of evidence is the timbremetrics triplet-agreement test: an audio encoder trained exclusively on FM synthesis data scores 68.4-69.3%, closing in on LAION-CLAP's 70.8-71.8% despite the latter being trained on vastly more general audio. The authors are also honest about scope: they show the interpretable byproduct that the learned output-level remapping resembles DX7's exponential gain curve, but don't overclaim -- the validation is on one synthesizer at one sampling point, with generalization to heterogeneous synthesizers or more complex graphs like effect chains still unproven.
